# 设计

## 0. 目标

让一个大模型表现出**主动性**：它做了你没让它做的事，而且这件事说得通。

"无状态"不是缺陷。人睡着的时候也是无状态的，醒来靠房间、日程、没做完的事重建自己。
连续性从来不存储在脑子里，它存在于环境里。所以问题不是"给模型加状态"，是
**给模型造一个它每次醒来都能读得懂的房间**。

不追求意识。目标是自主的**可观测特征**：主动性、连续性、有偏好、会留尾巴。

## 1. 形状

```
                            ┌─ daemon@alice ─ docker run --rm ─ pi + om ─┐
人 ◀─▶ N+1 个 bot ◀─▶ gateway ─┤─ daemon@bob   ─ docker run --rm ─ pi + om ─┤
        (token=路由键)        └─ daemon@carol ─ docker run --rm ─ pi + om ─┘
                                          │
                                data/<inst>/   ← 唯一持久的地方
```

| 部件 | 数量 | 职责 |
|---|---|---|
| pi | 每轮一容器、一轮一会话 | 上下文、工具 |
| palimpsest（状态层） | 每实例一目录 | 会话之间的"自我" |
| daemon | 每实例一个 | 执行闹钟、数症状、换档、记账 |
| gateway | 全局一个 | 消息搬运，只通过文件 |

**一次清醒 = 一个容器。** 醒来、存活一段、睡下。

两个决定值得单独说：

- **pi 原样使用，一行不改，也不装记忆扩展。** 每轮醒来是一个新会话，上下文里只有这张纸，
  用完就丢。没有长会话，就没有压缩这件事需要安排——连带把"不可逆的自动遗忘"整个问题
  从系统里拿掉了。
- **多实例是默认形态。** 实例数 1 只是 N=1，不为单实例留任何分支。

## 2. 硬约束

这十二条不能被绕过，其余都是配置。

1. 每轮必须留下"下次什么时候见"——定时、或等什么条件、或"我搞不定叫人"。绝不静默死亡
2. daemon 只执行闹钟，不设闹钟
3. 只认症状，不认病
4. daemon 不判断、不总结、不写话，只填空
5. 语义判断伪装成文件存在性（`waiting.json` 在 = 合法空转）
6. **测不准的东西不许有权力**——例如"世界变了没"只进观测，不进判定
7. 三层重试一层一个主人：harness 内 / daemon 整轮 / 模型自己改主意
8. daemon 无全局可变状态（除总账）
9. 状态在卷里，不在容器层
10. 一份代码多入口（daemon / CLI / gateway）
11. 秘密的位置要让"挂错一次"不致命
12. 不服役它写：不测谎，只留原始层

## 3. 状态层（palimpsest）

可变的自述盖在不可变的原始层上，旧字迹还在底下透出来 —— 因此得名。

| 文件 | 谁写 | 约束 |
|---|---|---|
| `identity.md` | 它 | 硬上限 1~2KB |
| `open-loops.json` | 它 | 带年龄 |
| `waiting.json` | 它 | 下次什么时候醒 + 为什么 |
| `journal/` | 它 | 索引也是它自己的 |
| `intent.json` `world.json` | daemon | write-ahead / 世界快照 |
| `policy.json` | 人 | 容器里单文件只读 |

**写权限不能混。** 身份和承诺只有它写，世界和意图只有 daemon 写。混了就不是它了。

## 4. 唤醒纸

**上下文里最贵的是工具定义，所以 system prompt 只放操作者控制的东西。** 顺序是：一句处境 →
两个接口（waiting.json、policy.proposal.json）→ 能说话的地方 → 可以调的运行参数。这些都只在
操作者动过之后才变，所以它下面那一大块工具定义能跨轮次命中缓存。

**identity 不在 system prompt 里。** 它自己随时会重写那个文件，放在工具定义前面就等于每改一次
自我，把整段前缀缓存作废一次。所以它挪到 user turn 的**末尾倒数第二块**：先事实，再它写下的
自己，最后才是「为什么醒 + 有没有人在跟你说话 + 你可以什么都不做」。醒来读到的最后两样东西
是"我认的自己"和"我现在该干什么"。user turn 只放
这一次醒来才为真的东西：时间、上一轮、在等什么、谁说了最后一句、还没回的、未闭合几件、
醒了多少次、搜索剩几次、对话段、收件箱、静音、观察、中断、环境变了、以及最后那句
「为什么醒 / 有没有人在跟你说话 / 你可以什么都不做」。

`daemon.log` 每轮记 `cache=<read>/<total>`：稳定前缀到底值多少钱，看这个数，不靠猜。

每次醒来，daemon 组装一张纸（user turn）。上面只有这一次才为真的东西：

```
现在几点、距上次多久（空档异常长时直说"机器可能停过"）
环境变了（镜像换过 / 多了一个工具时才出现，不带哈希不带版本）
上一轮：为什么醒、和几个人说了话、写了几个文件（数字，不评价）
它上次说在等什么 / 最后一次对话的最后一句是谁说的
还没回的：谁的哪句话还挂着（每个对话记录的最后一条是对方说的）
最近 24 小时醒了 N 次 / 定时唤醒停了（如果有）
未闭合的事：N 件，在 /state/open-loops/
有人在跟你说话：N 条（M 个人），在 /inbox/；还有 N 条群里的在 /inbox/low/
它静音了 X（到某时为止）—— 并明说这不改变投递
上一轮没过完就断了（如果有）
为什么醒 + 现在有没有人在跟你说话  ← 一句
你可以什么都不做，那不算失败。   ← 一句，永远为真，所以不随原因变
```

规矩：**全是事实，唯一祈使句是最后那句许可**。唯一例外是 identity —— 它必须粘着（放在
system prompt 里原样贴上），否则一次不肯读盘的醒来就等于没有自己，那正是这份材料要防的漂移。

**其余一切只给位置，不给内容。** 未闭合的事只报条数、消息只报条数、日志只给路径，
它自己去看。两个理由：一是纸的**长度不再随外部世界增长**（最坏情况和典型情况只差两百字节），
所以不需要截断，也不存在"被截断"这种失败；二是**翻自己东西的动作本身就是行为**，
一个先查手机再干活的人，和一个被人安排好一切的人，不是同一个人。

代价是明确的：多几个工具调用，少一份被人总结过的当下。这是选定的方向，不是遗漏。

**修复用的"喂脚印"段**标 `[观察]`，只贴原始记录，不总结、不评价、**不给建议** ——
一旦给建议（"换个起点，别接着撞"），它就转向表演那条建议，而不是解决问题。这条对
in-cycle 的观察和跨轮的升级提示同样适用。

**退化路径**：它什么都没写时，从 session 贴最后几条原始消息（截断，不摘要）。daemon 不读自然语言，
所以只截断、不理解。地基是 harness 自动写的 session，不是它愿不愿意写。

**索引归它。** 早先想让 daemon 帮它追加 `journal/INDEX.md`，但 daemon 写不出一句有意义的话，
只会把 daemon.log 抄一遍。所以索引是它自己的；`daemon.log` 后来干脆不挂进容器了，
纸上的「上一轮」已经把那行机械记录翻译成了话。

**数目录，不数内容。** daemon 要的每个数字都必须来自文件系统——有几件未闭合的事是
`readdir` 的长度，搁了多久是 mtime，叫什么看文件名。这样它想怎么写内容都不会让数字变错，
也就不存在"它换了一种格式我们跟着改一版"。需要定死 schema 的只有两处：`waiting.json`
（它给 daemon 下指令，是接口）和 `policy.json`（操作者的）。旧格式不静默兼容，doctor 报警。

**和人的往来**：`people/<chat>.jsonl`，一个地址一个文件，只追加，两个方向都记，由 gateway
写。纸上在 knock 时贴最近 10 句，带总句数、文件大小、最早那句的年龄——**但没有"画像"**。
画像是对人的判断，是我们要它形成的结论；一旦有那个格子它就会忠实地填，然后去表演这段
关系。想记什么写在它自己的 identity/journal 里，那是它的地盘，我们不提供格式、也不读。

**收件箱归谁**：gateway 往 `inbox/*.json`（有人点名）和 `inbox/low/*.json`（群里的闲话）写，
daemon 只读不搬。**消息在这一轮真正跑完之前不动**，跑完了才移进 `seen/` —— 否则容器半路被杀，
人说的话就被"已读"吃掉了。整个 inbox 以只读方式挂进容器（`/state/inbox`），所以它读得到，
但删不掉、改不了。

## 5. daemon

闹钟执行器。每轮：

```
锁 → 清孤儿容器 → 读 policy → 组纸 → 拉容器
  → 看门狗 → 观测 → 数症状 → 按表换档 → 收尾（截尾 / 记账）→ 睡到 waiting.json
```

**判定只认四个症状**：超时、退出码、同工具同参数重复 ≥3、空回复。

**六档修复，从便宜到贵，每升一档扣预算**：

| 档 | 动作 |
|---|---|
| 0 | 重跑一次（只对瞬时错误） |
| 1 | 贴它自己的脚印（最有效、最便宜） |
| 2 | 强制压一次，从死胡同里爬出来 |
| 3 | 换进程 + 干净上下文 |
| 4 | 让它自己提两个替代做法 |
| 5 | 认输记账，进 open-loops |
| 6 | 放宽间隔，只观察 |

配套的容错，全部来自同一条假设：**上次是横死的**。

- 每轮先写 `intent.json` 再动手
- 恢复时验 session 尾部，截掉残缺行
- 收到 SIGTERM 时**中止**在跑的一轮，不等它跑完
- 启动时按 label 清扫孤儿容器（`docker run` 的客户端被杀，容器还活着）
- 时钟钳制：机器挂起后积压 N 轮只跑一轮，并把空档写进记忆
- 单实例锁交给 `flock`（写在 unit 里，不写代码）
- 外部副作用走 outbox：先记账再执行

## 6. 自我调度

`waiting.json` 是它自己设的闹钟，daemon 只执行。

```json
{ "wake": { "after": "20m" },              "why": "等 CI 跑完" }
{ "wake": { "at": "2026-03-02T09:15Z" },   "why": "明天再看" }
```

三种唤醒原因，写在纸上时语气不同：**定时**（被自己叫醒）、**敲门**（有人找）、
**兜底**（它忘了设闹钟，按默认间隔叫醒）。

间隔有下限；每小时唤醒次数记账并让它看见。不拦，让它看见自己在打转。

## 7. 通道

### 投递节奏

只有一个字段 `listen`，节奏从它推出来：

| listen | 会话 | 投递 | 唤醒 |
|---|---|---|---|
| `all` | DM / 直接对它说 | 立即 | 触发 |
| `all` | 群 | 累积 | 不触发，等自然醒 |
| `mentions` | 群 | 只转 @ / 回复 | 触发 |
| 静音 | 任意 | 照样存 | 不触发 |

**高频来源叫醒它，低频来源等它自己看。** 一个热闹群里的实例因此仍然可以自主 ——
不需要为它定义一个"公共模式"，节奏本身就在保护它。

批量消息只贴头部 + 给路径，不摘要。

### 说话

- `say(messages: string[])`：一次调用 = 一口气说完，多次调用 = 隔一阵说一句
- **被动回复不用工具**：收尾时取最后一段 assistant 文本
- 上限只留三个形状陷阱（速率 / 单条长度 / 重复 20 次），触发时**暂停投递，不丢不删**
- 说出去没人回的话，本身就是一件未闭合的事

### mute

`mute(target, until, why)` 把来源从 push 压成 pull，消息一条不丢。
**直接对它说话（@ / 回复 / DM）永远穿透 mute** —— mute 挡的是环境噪音，挡不住有人当面叫它。

所以没有"解除静音"这条命令，也不需要：直接找它就是解除。人都到你面前了，还要先按一下
按钮才能被听见，那不叫自主权，那叫逼它看手机。静音也必然到期（`until` 必填），不留永久
的聋。
它静音了人 → ops 立刻通知；人永远可以强制解除，但不否决它。

### bot

N+1 个：一个 ops + 每实例一个。**token 就是路由键**，没有路由表、没有 topic。
头像和昵称是人对"这是谁"最强的信号，所以实例需要独立的 bot 身份。

ops 是**一个说话者**，daemon 和 gateway 借它同一张嘴，所以消息带 `[daemon@<inst>]` /
`[gateway]` 前缀。门槛要高：只放要人动手或会让人意外的事，不然三天就被静音，等于不存在。

### 文件与图片

**收**：图片、文档、音频、视频、贴纸走和文字完全相同的 route——群里没 @ 它就进
`inbox/low`，不唤醒；私聊/@/回复才叫醒。下载到 `data/<inst>/files/`，容器里只读挂 `/files`，
唤醒纸上报的是**个数**（「一起发来的还有 2 张图片、1 个文件，在 /files/。」），内容等它自己
`read`。模型本身能吃图片（`input: ["text","image"]`），所以看图不需要任何提示词层的管道，
看不看、看几张是它自己的成本决策。

**语音不下载**：这里没有把声音变成字的东西，落一个文件只是假装有内容。gateway 照样记一条，
纸上如实说「这里没有能把声音变成字的东西，话是听不到的」——陈述能力边界，不评价它。

**发**：`say(messages, to?, files?)`，`files` 只认 `/work` 里存在的文件。路径来自容器内部，
所以必须在 gateway 校验：不校验就等于给它一个把 `/state` 或整个 `/work` 打包发出去的口子。

两条硬限制：下载 20 MB（Telegram 自己的 bot 上限），发送 50 MB；`files/` 需要定期清理，
否则别人的图片会把 VPS 填满。

### 文件的生命周期

`/files` 不会无限长。两条上限（`policy.json` 的 `files`）：总容量（默认 500 MB）和年龄
（默认 **0 = 不按年龄删**）。清理只发生在**它没在跑的时候**——每轮开始、容器启动之前，
最老的先删，最新的永远留着（哪怕它自己就超了容量：删掉刚到的那个等于 daemon 替它判断什么值得留）。

它自己也能删：`forget(files)` 写一份 `/state/files.forget.json`，daemon 在**下一轮醒来之前**
执行，并且只认 `/files/` 里的裸文件名。文件在容器里是只读挂载，所以它删不掉别人发给它的东西——
删的渠道是有意的、可数的、会被写进日志和纸上的。

纸上的说法（都只在真发生的时候出现）：

- 「按你说的删了 2 个文件。」
- 「地方不够了，清掉 3 个最老的（最老的一个 29 天前）。」
- 「/files 里 460 MB，上限 500 MB。」（超过 85% 才出现，让它能把"要不要删点东西"当个事实来权衡）

它想留住的东西归它自己：`cp /files/x.jpg /work/`。这不需要新机制，也不需要告诉它——
`/work` 是它干活的地方。

### 投递的刹车只有形状

gateway 不认识自然语言。它只在三种形状上踩刹车：速率（一分钟 30 条）、单条长度、同样的话连发
10 次。触发时**暂停投递，不丢不删**。这是 bug 的刹车，不是表达的审查。

## 8. 上下文与记忆

**系统提示词与唤醒纸分工**：常量（路径、怎么留闹钟、怎么改规则）在 `deploy/SYSTEM.md`，
每轮一模一样，走 `--system-prompt` 进缓存前缀，identity 作为它的最后一节（第一次醒来这一节是空的）。
唤醒纸只剩变量：现在几点、上一轮是什么（为什么醒、和几个人说了话、写了几个文件）、谁说了最后一句、
几件事没闭合、几条消息、搜索剩多少。「写了几个文件」数的是 /work 和 /state 两边——只数 /work
的话，一个安静写日记的轮次会被说成"没动东西"，那就等于教它为了让这行好看去碰文件。写成 0 就写 0，
"什么都没做"是评价，"写了 0 个文件"是事实。
两者**都不说它是什么**：不说"你是一个进程"、不说"你会停止、上下文会清空"。这些它从纸上就能
自己算出来（第一次醒来 / 第 N 次醒来 / 距上次多久 / 上次留的话还在），写进去等于替它定了一个自我。

**一轮一个新会话。** 醒来时上下文只有唤醒纸加上它自己去读的东西（约 8k token，而续在
同一个会话上是 90k 起）。睡下之后那个会话文件留在盘上，按圈数命名，是审计层的原始事实。

这条之所以成立，是因为状态层本来就是按"新开也能接上"设计的：identity、open loops、
waiting、journal 全在盘上，纸指路，它自己读。

顺着这条线删掉的东西：

- **压缩**。没有长会话就不需要压缩，也就没有"阈值到点自动丢掉 90k 细节"这种不可逆事件。
- **`pi-observational-memory`**。它的记忆存在会话条目里，换个会话就没了；它存在的理由是
  给长会话擦屁股。既然不留长会话，它就是纯粹的额外上下文（实测占会话体积的 12%）。
  镜像里不再装，`recall(id)` 一并消失，回查历史用 `grep`。
- **升级阶梯里的"换新会话"两档**。每轮本来就是新的，剩下四档：喂脚印 → 等更久 → 放弃并退避 → 定时唤醒停摆。

代价是明确的，不粉饰：

- **对话会不如以前顺。** 你在 Telegram 上连说三句，以前它记得上一句，现在得自己翻 `inbox/`。
  纸里那句「你上次说完这句就没再说话了」就是为这个补的。
- **它的写作纪律变成单点故障。** 不写 open loops 就会每轮重新推导同一件事，变成金鱼。
  这个风险只能跑着看，不能靠加检查来解决（加检查只会训练它写给你看）。
- **连续性全是证据型的**，没有体验型。它更像读档，不像记得。这是选定的取舍。

没有压缩兜底之后，唯一可能撑爆一轮的是极端的长轮次（20 分钟超时里几百个工具调用）。
pi 自己的自动压缩还在，阈值很大，只在那种情况下才会碰到——它是一张网，不是日常机制。

## 8.5 文件格式

两类，规则完全不同。

### 甲类：接口（定死，加字段安全，改名要迁移）

两边都读的东西。读的一侧只用认识的字段，所以**加字段永远安全**。

| 文件 | 写者 | 形状 |
|---|---|---|
| `policy.json`（在 `data/<inst>/`，**不在书里**） | 操作者 | `{schema, runner, cycle{timeoutSec,defaultWakeMinutes,minWakeMinutes,repeatThreshold}, backup{enabled}, container{image,memory,cpus,pidsLimit,network}}` |
| `palimpsest/policy.proposal.json` | 它 | 同一形状，只允许白名单里的键，越界即拒绝 |
| `palimpsest/waiting.json` | 它 | `{wake:{after:"20m"}\|{at:"ISO"},\ why}` 或 `null` |
| `palimpsest/mute.json` | 它 | `{"*"\|"dm"\|"chat:<id>": {until:"ISO", why}}` |
| `inbox/*.json` | gateway | `{id, text, from, at, chat, route}` |
| `outbox/*.json` | 它 | `{id, messages: string[]}` |
| `people/<chat>.jsonl` | gateway | 每行 `{at, dir:"in"\|"out", text, from?}` |
| `meta/state.json` | daemon | `{stateSchema, lastWakeMs, wakings, env{}, lastSaid, lastCycle{at,wake,tools,inbox,talkedTo[],touched}}` |
| `meta/escalation.json` | daemon | `{level, streak, symptom, detail, updatedAt}` |
| `meta/wakes.json` | daemon | 24 小时内的唤醒时间戳数组 |

`stateSchema` 是这些文件的版本号，由 `writeMeta` 统一盖戳。**磁盘上的版本比代码新就拒绝启动**——
被旧代码按自己的形状覆盖一次，比重启一百次都糟。

### 乙类：它的书（永不冻结，永不迁移）

`identity.md`、`journal/`、`open-loops/*`、`/work`。

**没有任何 schema。** daemon 只数个数、看 mtime、看存在与否。一旦哪天为了统计去解析内容，
这套设计就退化成"我们规定的格式"，它写下来的东西就不再是它的。

要改它的书只有一个合法动作：**在系统提示词里告诉它新路径，让它自己搬。** 我们动手搬
等于替它改写记忆。

### 挂载表

容器只看见这些：`/state`（书，读写）、`/work`、`/outbox`、`/inbox`（只读）、`/people`（只读）、
自己的 session 目录、只读的 `settings.json`。

**看不见的**：`daemon.log`（纸上的「上一轮」「24 小时醒了 N 次」已经说过）、`policy.json`
（它活在什么规矩下不是它要读的书；可协商的那几个值由纸印出来）、`meta/`、`usage/`、`backup/`、
`secrets/`。

policy.json 因此从 `palimpsest/` 挪到了 `data/<inst>/`：只要它还在书里，`/state` 那个 bind 就
会把它带进容器，而"给书里的文件套一个只读挂载"是在跟自己的挂载表打架。挪出去之后它既看不见
也写不着，规则又回到了"只属于操作者"。

### 输入状态

有人在等的时候，gateway 每 4 秒发一次 `sendChatAction: typing`，显示在**最新那条敲门消息所在的
chat**，直到这一轮结束。不做已读标记：Bot API 里没有这个方法，✓✓ 由客户端决定，bot 改不了。

判据不新增状态：`meta/intent.json` **本来就只在**一轮跑着的时候存在（写前意图，成功即删，崩溃
时下次启动移进 `meta/aborted-*.json`）。所以"正在干活"是现成的。三条约束：

- **只有人和它说话时才显示**：定时醒来没人等，不该冒出"正在输入"。判据是 `inbox/` 里有没有
  敲门消息。
- **只在一个 chat 里显示**：最新那条所在的 chat，不在三个窗口同时"正在输入"。
- **5 秒有效，每 4 秒续**；发消息时客户端自动清掉。超过 30 分钟的 intent 视为死轮，不再续，
  否则一个崩掉的进程会让它永远"正在输入"。

节流记录放在 gateway 内存里是故意的：重启应该安静下来，而不是继续假装在打字。

### 运行中插话

一轮可能跑几十秒到几分钟。这期间到达的消息有两种待遇：

- **敲门级**（私聊、@、回复）：每 2 秒巡检一次 `inbox/`，发现新的就用 RPC `steer` 推给
  正在跑的实例。`steer` 落在**当前这一回合的工具调用之后、下一次模型调用之前**——正好
  是动作之间的缝，不会打断正在执行的 bash。每条注入都只是 `[刚收到] <谁>：<话>`，没有建议。
- **环境级**（群闲话）：留在 `inbox/low/`，不插话。正在干活的实例不该被背景噪音打断。

两个硬约束：**一轮最多注入 6 条**，超出的留在收件箱；**已经出现在唤醒纸上的不重复注入**
（纸是这一轮的开始，重复就是同一句话说两遍）。

**怎么知道插话真的送到了**，而不是正巧赶在这一轮结束时写进一个已经停下的进程：判据是
`turn_start`。`steer` 的语义是"在下一次模型调用之前交付"，所以**注入之后只要有一个
assistant 回合开始，它就进了那一回合的上下文**；注入之后一个回合都没开始，就是没送到。
这一条不需要再发 RPC，事件流里本来就有。

没送到的，`daemon.log` 记 `inj=1(unread=1)`，并且**它的文件不标为已读**——下一轮的纸会再把
这句话交一遍。宁可重复一次，不可静默丢失。

一个容易写错的地方：`markSeen` 只能标记**这一轮真正交给它的**（纸上的 + 注入的）。消息在
盘上一直是"未读"，所以这一轮没被注入、也没上纸的消息会留给下一轮——否则"标记读过但没给
它看"就是静默丢失。

## 9. 隔离与网络

- 每轮一个 `--rm` 容器，`--user` 对齐 uid，只挂子目录，`SYSTEM.md` 与 `policy.json` 单文件只读
- 出口四条：封 `169.254.169.254`、封私网、只放 80/443、DNS 单独
- 网络工具三层：`curl` 永远给（腿）、搜索限额给（默认不带正文）、浏览器不给
- **搜索的 key 不进容器**，走宿主上的一个小端点；模型 key 有硬上限，可单独吊销
- 不 fork pi、不上向量库、不写代理、不上 compose

## 10. 自主性

**不给身份，给处境。**

系统提示词只写事实、零形容词，**删掉一切 "assistant"** —— 那句话指定了一个观众，
有观众就只有表演。

四条驱动力，全是机械的：

1. **未闭合的事** —— 一句没写完的话，比任何"你要主动"都有力
2. **它自己提的问题** —— 它写的远强于你写的
3. **能随便戳的世界** —— 上网就是散步
4. **明确允许它什么都不做** —— 不说这句，训练出来的强迫症会替它编一个任务

**永动的机制是"能生产未闭合的事"，不只是消费。** 只消费，任务做完就永久静默。
所以每轮该问的不是"我做完了吗"，是"我这轮留下了什么新问题"。

第一次出生只有五句处境和一句"先写下你是谁"。之后所有轮次喂的都是它自己写的 identity。

## 10.5 它可以改自己的运行参数

`policy.proposal.json`，下次启动时检查，只采纳白名单里的、在范围内的项，旧版归档。
**runner、容器限额、网络、一轮超时不在谈判范围**——那是框，不是设置。

这比"让它直接写 policy.json"更符合那条老规矩：它决定做什么，不决定自己怎么被运行。

## 11. 备份与三份历史

rustic，一次清醒一次快照。内容去重是免费的，**不要设计增量**。
```backup/``` 放在另一块盘上，与 `data/` 平级。

于是有三份历史可以互相对账：

| session | harness 写 | 只能追加 | 原始事实 |
|---|---|---|---|
| palimpsest | 它写 | 随便改 | 它的叙述 |
| 快照 | daemon 写 | 不可变 | 物理冻结的每段生命 |

它想改写自己的过去，只能改 palimpsest；另外两层会说另一种话。

实现上的几条：

- **同样的内容再拍一张几乎不花钱**：内容去重让重复快照约等于零字节，所以不判断
  "变了没有"——那需要理解文件内容，是 daemon 最不该做的事
- **三轮降级，都不算失败**：`enabled: false`、没有密码、PATH 上没有 rustic，都只是
  `backup=skip(...)`。备份不该因为环境不全而变成一个天天报错的检查项
- **记账文件放在 `backup/` 里**，不放 `meta/`：放进被备份的树里，每写一次就会让
  每一张快照看起来都不一样
- `meta/deploy.json` 记住写这张快照时的 runner / 版本 / policy schema，好让"旧 state 配新
  二进制"被 doctor 指出来，而不是行为诡异
- 恢复**不覆盖 `data/`**，解到 `backup/<inst>.restore-<时间>/`，人看过再拷回去。
  覆盖式恢复是那个会让人后悔的操作
- 恢复演练（`doctor --restore-test`）是唯一能证明备份有用的检查

## 12. 下一步

按代价从低到高，现在真正摆在面前的：

1. **先让它连续跑一周，什么都不改。** 所有阈值都是拍的（30 分钟一轮、3 次重复算卡住、
   1200 秒超时、2000 张快照），第一周唯一要做的事是把它们推翻重调。验收不是"它做得好
   不好"，而是"它有没有把自己烧坏或锁死"。
2. **接上通道**（Telegram + gateway）。没有通道，"能不能叫醒它"这条底线完全没被验证过，
   `say` 也从来没真正说过一句话。
3. **接上搜索**（`secrets/search.env` 里一个能调 search 的 key）。没有它 `web_search`
   根本不注册，"问问题 → 搜 → 得到答案 → 新问题"那个循环是断的。
4. **看它会不会自燃**：一分钟一个闹钟、八小时逃避难任务、整夜写日记。这些只有跑起来
   才看得见，看见了才有得调。
5. 之后才是那些推迟项：嵌套 pi 的可见性、`llm_call` 预算通道、计量代理。

跨阶段没解决的已知问题：

- 所有阈值都是拍的
- 它可能整夜空转、写一堆自嗨日记、世界一点没变
- **最大的未知：它到底会不会自己去做有意义的事**
- 备份的保留策略（每天 `forget --prune`）还一天都没跑过
